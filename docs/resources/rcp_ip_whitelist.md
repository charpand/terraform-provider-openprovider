# openprovider_rcp_ip_whitelist (Resource)

Manages the IP whitelist for the OpenProvider control panel (RCP) of one contact, through `PUT /v1beta/contacts/{id}` (`rcp_client_ip_list.allow`).

The contact is the login contact, an object with a numeric id under `/contacts`, and not a customer handle from `openprovider_customer`. The resource does not create or delete the contact; it owns only the contact's `allow` list.

~> **Warning: lock-out.** A whitelist refuses every address that is not on it with error 10005 (Access Denied). Include the address you apply from and any CI runner that applies this configuration. The API replaces the whole list on every write, so entries added by hand outside Terraform are removed on the next apply.

~> **Warning: destroy.** An empty list switches the whitelist off. By default (`on_destroy = "retain"`) destroying the resource leaves the whitelist in force and only forgets it in state. With `on_destroy = "clear"` the list is emptied and the control panel is open to every address. The `on_destroy` value is read from state, so apply a change to it before destroying. An empty `allow` is rejected in configuration for the same reason.

The contact's `deny` list is neither read nor changed. Drift (an address added or removed outside Terraform) shows up in the next plan.

## Example Usage

### Basic

```terraform
data "openprovider_contact" "login" {
  id = "123456"
}

resource "openprovider_rcp_ip_whitelist" "login" {
  contact_id = data.openprovider_contact.login.id

  # Include every address you apply from, CI runners too: an address that is
  # not on the list is refused with error 10005 (Access Denied).
  allow = concat(
    ["203.0.113.10", "2001:db8:1::/48"],
    var.ci_runner_ips,
  )
}

variable "ci_runner_ips" {
  type    = list(string)
  default = []
}
```

### Switch the whitelist off on destroy

```terraform
resource "openprovider_rcp_ip_whitelist" "login" {
  contact_id = 123456
  allow      = ["203.0.113.10"]

  # Destroying this resource empties the list, which switches the whitelist
  # off and opens the control panel to every address.
  on_destroy = "clear"
}
```

## Schema

### Required

- `allow` (Set of String) The addresses allowed to reach the control panel: IPv4 or IPv6 addresses, or CIDR blocks. At least one entry is required, since an empty list switches the whitelist off. Entries are compared as written, so write an address the way the API returns it.
- `contact_id` (Number) The numeric id of the contact whose control panel access is restricted (the login contact, not a customer handle). Changing it replaces the resource.

### Optional

- `on_destroy` (String) What destroying this resource does at OpenProvider. `retain` (the default) only forgets the whitelist in state: it stays in force at OpenProvider. `clear` empties the list, which **switches the whitelist off** and opens the control panel to every address.

### Read-Only

- `id` (String) The contact identifier, the same as `contact_id`.



## Import

Import the whitelist of a contact using its numeric id. `on_destroy` is set to `retain`.

```shell
# Import by the numeric contact id
terraform import openprovider_rcp_ip_whitelist.login 123456
```
